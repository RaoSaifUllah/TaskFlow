# ADR-002: EF writes and Dapper scoped reads

Status: accepted baseline, 2026-10-01.
Implementation evidence: see ../Implementation-Status.md; acceptance is not a verification claim.

## Decision
Use aggregate-specific EF repositories and a scoped Unit of Work for writes; use parameterized Dapper projection services for read-only queries.

## Rationale and consequences
Read credentials have explicit SELECT grants. Every query must enforce membership and visibility; EF filters do not protect Dapper.

Source: document/02-Software-Design.md. No deviation from the supplied architecture.
